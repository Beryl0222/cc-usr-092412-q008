# 医者荣誉贡献档案

本仓库保存该服务的领域资料与最小事件约定，供业务团队在统一语义上继续建设。

## 已有内容

- `contracts/domain.schema.json`：领域事件的基础字段、聚合类型和事件名称。
- `data/sample.json`：可用于联调的中文样例记录。
- `src/validator.js`：只负责校验基础事件信封，不包含业务流程。
- `src/adjudication.js`：贡献合议与发布冻结服务（事件溯源，见下）。
- `tests/`：验证样例与基础约定、合议业务规则保持一致。

## 贡献合议与发布冻结

院务办公室发布团队荣誉前，跨系统（主刀、护理、转诊、研究支持）汇集候选贡献，经专业代表与荣誉委员会合议后签署生效名单，并冻结患者案例的展示同意版本。规则要点：

- **提名门槛**：候选贡献必须指向具体工作事实、该事实发生时有效的资质、可公开定位的证据；涉及患者案例还须声明展示范围。
- **同名只提示**：同名不同人只产生 `SAME_NAME_HINT_RECORDED` 提示，绝不自动合并身份。
- **分级合议**：各专业代表（`FACT_CONFIRMED`）只能确认本专业事实；委员会处理重叠（`OVERLAP_*`）、遗漏（`OMISSION_*`）与异议（`DISPUTE_*`）。
- **异议局部暂停**：异议期间只暂停争议贡献，名单签署时将其排除（`disputed_paused`），不阻断无关联的团队部分。
- **同意版本冻结**：`CONSENT_VERSION_FROZEN` 固化当时同意版本与范围；患者撤回同意（`CONSENT_WITHDRAWN`）后遮罩证据（`EVIDENCE_MASKED`），但不删除任何历史决议。
- **资质更正留痕**：`QUALIFICATION_CORRECTED` 追加新资质，原始资质保留在授予理由链路上。
- **材料处置**：未发布材料只能替换（`MATERIAL_REPLACED`），已发布材料只能更正或撤回（`MATERIAL_CORRECTED` / `MATERIAL_RETRACTED`）；封存前所有受影响材料必须处置完毕。
- **并发签署**：`signRoster` 使用 `expectedVersion` 做乐观并发；完全相同的回执可幂等重放，内容变化的并发签署进入 `SIGNING_HELD` 待核，经委员会复核（`HELD_SIGNING_RESOLVED`）后才形成新生效版本，始终只有一版生效名单。
- **最终档案**：`sealArchive` 产出 `internal`（完整贡献、资质链路、遮罩证据、异议/重叠/待核记录、处置经过）与 `public`（仅生效名单、可公开且未遮罩证据、必要的更正/撤回告示）两份分离视图，可还原每项荣誉为何授予、哪些证据被遮罩、后来如何处置。

## 领域边界

当前资料围绕团队贡献、资质核验和患者同意整理。事件一旦被接收，其标识、发生时间和版本不应被原地改写；业务更正应产生后继记录。涉及个人、机构或商业敏感信息时，调用方只读取完成职责所必需的字段。

## 本地检查

```bash
node --test
```

## 测试与构建

测试命令：

```bash
npm test
```

编译或构建命令：

```bash
npm run build
```

这些命令可在单个 Linux 应用容器内执行，不需要另行启动外部服务。
